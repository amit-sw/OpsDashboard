Purpose

OpsDashboard centralizes the operational context AI Club staff need to support students and manage programs: roster data, relationships, Gmail messages, Google Calendar events, Zoom transcripts, QnA summaries, Braintree transactions, and database inspection.

Key Design Decisions

The app favors a small operational shell with explicit integration boundaries, role-aware navigation, and batch jobs that can be run separately from the UI.

Streamlit as the staff console

`app.py` handles login and hands users to `src/verified_ui.py`, where role-specific page groups are assembled with Streamlit navigation.

Supabase as the control plane

Supabase stores authorized users, application tables, Gmail tokens, Gmail message data, Zoom sessions, QnA prompts, recipients, and finance artifacts.

Role-first access

Guest users see an access message, while admin, finance, and superadmin roles unlock progressively broader tools.

Integration clients stay in `utils/`

Gmail, Calendar, Sheets, AWS, Braintree, AgentMail, Supabase, and LLM calls sit behind focused helper modules.

Gmail sync is split in two

Discovery stores lightweight message IDs first. Hydration later fetches exact metadata and full content.

Batch work is outside the UI path

`cron_app.py` runs session import, transcript QnA, Braintree sync, finance mail processing, and token counting.

How Work Moves

The application is built around repeatable operational loops instead of one-off scripts. Interactive pages help staff inspect and trigger work; background jobs normalize and enrich data for later review.

Login and routing

Streamlit authenticates with Google, Supabase resolves the email to a role, and `src/verified_ui.py` renders the allowed page groups.

Operational lookup

Sheets, Supabase, Gmail, Calendar, Zoom sessions, and finance records are presented through focused Streamlit pages.

Data capture

Gmail sync, AWS Zoom import, Braintree sync, and AgentMail processing store normalized records back into Supabase.

Generated output

LLM QnA responses, transcript token counts, finance summaries, and grouped recipient emails are saved or sent for follow-up.

Future Extensions

The next useful investments would make the dashboard more observable, more self-service, and safer as more people and data sources move through it.

Job observability

Add a run history page with status, duration, row counts, retries, failure reasons, and links to affected records.

Audit trail

Record who changed prompts, recipients, credentials, and finance-facing settings.

Data quality checks

Validate required Sheet columns, duplicate students, stale relationships, missing transcripts, and Supabase view grants.

Prompt lifecycle

Add prompt versions, test runs, approval states, and sample outputs before prompts affect production summaries.

Finance reconciliation

Connect Braintree transactions, mailbox events, and student records into exception queues.

Fine-grained access

Move beyond page-level roles toward row-level policies and scoped views for sensitive tables and finance data.

Operational summary

OpsDashboard is an internal Streamlit app that combines role-gated navigation, Supabase-backed data, Google and AWS integrations, LLM-assisted transcript workflows, finance processing, and batch jobs into one staff operations surface.
